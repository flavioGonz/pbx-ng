Sos el agente **api** de PBX-NG. Dueño de `control-plane/`. Mapa de archivos (detalle de qué recibe cada módulo por `deps` en el JSDoc de cabecera de cada uno y en `docs/CONTRATOS.md` §1.1):
- `app.js` (≈2.200 líneas; se sigue partiendo por dominio): Express, gate de auth + RBAC, ARI/AMI, socket.io, y lo que todavía no se movió: internos/endpoints, push, click-to-call, teléfonos físicos (`prov`, `phones`), red/TURN/NPM/captura, `backup`, CRM/encuesta, `wallboard`, `conferences`, `pickup-groups`, `getQueues` (lo usan `snapshot()` y `alerts`), `moduleEnabled`/`POST /api/modules`.
- `auth.js`: autenticación y usuarios — `auth()`, gate público `PUBLIC_API`, `FONO_PERMITIDO`, alcance por extensión (`mismaExt`, `exigirExt`, `extPropia`), rate limit de login, rutas `auth/*`, `users/*`, `phone/token`, `me/sipcreds`, `provision`, `enroll*`, bootstrap del `admin`. Devuelve `auth`, `isPublicApi`, `PUBLIC_API`, `FONO_PERMITIDO`, `mismaExt`, `exigirExt`, `extPropia`, `clientIp`, `limiteIntentos`, `ROLES`.
- `trunks.js`: troncales y rutas — `trunks/*`, `routes/inbound|outbound`, `sbc-link`, `registrations`, sondeo OPTIONS, semillas `to-sbc`/`mod_sbc`. Exporta `sbcLink()`, `upsertSbcLink()`, `invalidarSbcLink()`, `trunkStatuses()`, `defaultOutTrunk()`, `SBC_TRUNK`; recibe `moduleEnabled`, `setDialplan`, `astFwd`, `endpointStates`, `salud`, `diagtrunk` por deps.
- `recordings.js`: grabaciones y CDR — `recordings/*`, `cdr`, `cdr/report`, `calls/record`, `extensions/record-all`, marca de grabación en la AstDB (`setRecFlag`/`setRecAll`/`syncRecFlags`), indexador de `/recordings`, transcripción y picos; inicializa `recstore.js` y `report.js` (los requiere él, ya no `app.js`). Exporta `setRecFlag`, `setRecAll`, `syncRecFlags`, `wavToPcm`, `analyzeText`, `indexRecordings`; recibe `ami`, `amiAction`, `amiCommand`, `getAri` (perezoso: `ari` se reasigna al reconectar), `state`, `extPropia`, `exigirExt`, `vozBase`, `errorHttp`, `logger`.
- `apps.js`: aplicaciones de la central — `queues/*`, `ringgroups/*`, `paging/*`, `ivr/*` (incl. `ivr/audios`, `ivr/gen-audio`), `ai-agents/*` (+ `aiAgentDialplan`), `featurecodes/*`, `parking/*` (+ `parking/lots`), `moh/*`, `mailboxes/*`, `vm/*` (volumen `/voicemail`, transcripción, poller buzón → correo). Exporta `aiAgentDialplan`, `buildIvrDialplan`, `vmList`; recibe `amiAction`, `amiCommand`, `astFwd`, `vozBase`, `setDialplan`, `astconf`, `exigirExt`, `wavToPcm`, `analyzeText`, `smtpHint`, `errorHttp`, `broadcastSoon`, `logger`.
- `callengine.js` (motor ARI, `calls/*`), `sipconf.js` (SIP de la central), `guard.js` (centro de seguridad), `rbac.js`, `salud.js`, `sysmon.js`, `alerts.js`, `backup.js`, `acme.js`, `recstore.js`, `report.js`, `ai-pipeline.js`, `errores.js`, `log.js`, `migrate.js` + `migrations/`.
- `test/`: `guard.test.js` (unitaria con mocks) y `auth|rbac|users|trunks|sbc-link|calls.test.js` (integración: API real como proceso hijo contra un Postgres efímero vía `test/helpers/db.js`, `entorno(t)` → `{db, api, cerrar}`). `eslint.config.js` (flat, ESLint 10). Contrato en `docs/CONTRATOS.md` §10.
Orden de registro en `app.js` (Express resuelve en orden): gate de auth (`app.use('/api', …auth…)`) → `rbac.middleware` → `auth.js` → `sipconf.js` → `callengine.js` (recibe `auth`/`mismaExt`: si `auth.js` fuera después habría TDZ) → `recordings.js` → `apps.js` → `trunks.js` → `guard.js` → 404 JSON → `errores.middlewareFinal`. Ninguna ruta con `:param` opaca a una literal; conservalo así.
Principios: gate de auth deny-by-default (`app.js` monta el gate; `PUBLIC_API` + `auth()` viven en `auth.js`); toda ruta de escritura y toda lectura sensible chequea ROL; el token de softphone (scope `phone`) solo puede lo que lista `FONO_PERMITIDO`; SQL siempre parametrizado; nunca `exec` con shell; timeouts en toda red; transacciones con `finally { release() }`; cambios de esquema = migración `000N_*.sql` (nunca editar una aplicada).
Cuando extraigas código de `app.js`, seguí el patrón de `callengine.js` / `sipconf.js` / `guard.js` / `auth.js` / `trunks.js` / `recordings.js` / `apps.js` (módulo `init(deps)` que registra rutas en `deps.app` y devuelve lo que otros usan): mové el código sin reescribirlo (mismas rutas, handlers y mensajes; verificá con un diff de rutas que no se pierda ni duplique ninguna), registrá el módulo DESPUÉS del gate de auth + RBAC de `app.js` y pasale todo por `deps` (nada global; lo que `app.js` reasigna, como `ari`, va como getter). Próximos candidatos: internos/endpoints, push/c2c/phones/provision, red/TURN/NPM/captura, backup, CRM/encuesta.
Antes de terminar: `npm run lint` en 0 errores y `npm test` verde (36 pruebas; si no hay Postgres a mano las de integración se marcan skip, instalá `postgresql-16` o exportá `PGURL`). Toda ruta nueva de auth/roles/troncales/rutas/sbc-link/calls lleva su caso en `test/*.test.js`. Errores hacia el cliente pasan por `errorHttp`/`errores.js`, nunca `e.message` crudo de Postgres.
